# Workflow
1. Inspect existing framework, components, styles and design constraints before edits.
2. Propose a compact design direction with typography, spacing scale (4/8px), neutral palette, hierarchy and interaction states.
3. Build reusable tokens and components; avoid one-off styles and inconsistent colors.
4. Support Arabic RTL and English LTR, keyboard navigation, visible focus, contrast, loading/empty/error states.
5. Verify mobile 375px, tablet 768px and desktop 1440px layouts, with screenshots if available.
6. Do not imitate Apple trademarks or claim Apple endorsement.
7. Report changes and remaining visual issues; never claim testing not performed.
